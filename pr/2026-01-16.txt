X '보상형 게시' 퇴출에 인포파이 모델 흔들…셀라 네트워크가 제시한 '플랫폼 리스크 탈출구'

부제목: 'X'의 API 회수로 확인된 단일 플랫폼 의존 한계…셀라 "정책 인식·다중 소스 웹 액세스로 재구축 지원"

2026년 1월 16일

소셜미디어 플랫폼 X가 '보상형 게시' 앱을 API 약관 위반으로 규정하고 관련 서비스의 API 접근을 차단하면서, 단일 플랫폼 API에 의존하던 참여형 비즈니스의 취약성이 현실로 드러났다. 카이토(Kaito), 쿠키(Cookie)가 서비스 종료를 발표했고, 월체인(Wallchain), 지트(xeet) 등 유사 서비스도 영향권에 들었다. 업계에서는 "API 차단에 쿠키리스(Cookieless) 전환까지 겹치면 참여 수집과 식별 자체가 불가능해진다"는 우려가 커지고 있다.

이런 환경 변화 속에서 셀라 네트워크(Sela Network)는 특정 소셜 API에만 의존하지 않는 '웹 액세스 인프라'를 대안으로 내세우며, "플랫폼 변화에도 플랫폼 의존 제품이 죽지 않게 만드는 인프라"라는 메시지를 강화하고 있다.

니키타 비어 X 프로덕트 총괄은 15일(현지시간) "X에 글을 올리면 금전적 보상을 주는 앱은 API 약관상 더는 허용되지 않는다"고 밝혔다. 보상형 구조가 "AI가 생성한 저품질 게시물과 리플라이 스팸을 대량으로 유발했다"는 취지의 설명이다. X는 규정 공지에 그치지 않고 접근 차단을 즉시 집행했고, 이로 인해 API에 의존하던 서비스들의 운영 체계가 직접적인 타격을 입었다.

인포파이(InfoFi) 서비스 다수는 X API를 통해 게시·리플라이·리포스트 등 참여 데이터를 수집하고, 이를 점수화해 순위를 산정하고 보상을 분배하는 체계를 구축해왔다. API가 막히면 수집-검증-랭킹-지급으로 이어지는 전체 밸류체인이 동시에 멈춘다. 시장에서 "인포파이 다 중지"라는 말이 나온 배경이다.

■ 셀라 네트워크의 해법: '플랫폼 교체'가 아닌 '의존 구조의 교체'

셀라 네트워크는 이번 사태를 "인포파이의 종말이 아니라, 단일 플랫폼 의존 모델의 종료"로 규정한다.

셀라 네트워크는 이미 '탈중앙 노드 기반 웹 액세스 인프라'를 구축해 운영 중이다. 전 세계에 분산된 노드가 웹 작업을 실행하고, 여러 소스에서 신호를 수집한다. 한 플랫폼의 API가 막혀도 다른 소스와 경로를 통해 운영을 이어갈 수 있는 '복원력'을 인프라 단계에서 확보한 구조다. 셀라 네트워크는 자체 제작한 탈중앙 마케팅 툴 '그로울옵스(GrowlOps)'를 통해 이 인프라의 실효성을 검증했다. 그로울옵스는 보상을 미끼로 야핑(yapping)을 대량 생산하는 구조가 아니라, 오거닉하게 발생하는 행동을 측정·강화해 기여를 정당하게 보상하는 방식으로 설계됐다.

셀라 네트워크는 "개발자가 분산 노드를 통해 웹 작업을 실행하고 웹 신호를 수집할 수 있는 탈중앙화된 웹 상호 작용 계층을 구축했다"며 "정책 인식 기반의 책임 있는 사용과 다중 소스 복원력에 집중하고 있다"고 밝혔다.

구체적으로 △분산 노드 기반 웹 작업 실행 △다중 소스 신호 수집 △검증 가능한 로그·증적 확보 △대체 경로 자동 전환을 지원한다. 운영팀이 특정 API 하나에 사업 전체를 걸지 않아도 되는 환경을 제공한다.

■ '정책 인식' 설계: 우회가 아닌 공존

셀라 네트워크가 강조하는 또 다른 키워드는 '정책 인식(Policy-Aware)'이다.

SEO가 검색엔진을 속이지 않고 콘텐츠를 최적화하듯, 셀라는 플랫폼의 알고리즘과 충돌하지 않는 방향으로 작동한다. 무분별한 자동화나 약관 우회가 아니라, 각 사이트·플랫폼의 정책과 제한을 인식하고 준수하는 방식이다. 이를 통해 장기적으로 지속 가능한 운영이 가능하다.

셀라 네트워크는 "스크래핑이나 약관 우회가 아니라, 허용된 범위 내에서 다중 소스를 활용해 단일 장애점을 제거하는 것이 목표"라고 설명했다.

■ 인포파이의 다음 단계

업계에서는 향후 인포파이형 서비스가 생존하려면 설계 방향 자체가 달라져야 한다는 관측이 많다.

첫째, 한 플랫폼의 타임라인을 '공략'하는 구조에서 벗어나 여러 채널과 웹 신호를 조합해 참여를 검증하고 캠페인을 운영하는 방식으로 전환해야 한다. 둘째, 측정과 귀속을 쿠키에 과도하게 의존하지 않는 구조가 필요하다. 셋째, 데이터 수집과 실행을 분리해 리스크를 분산하는 구조가 요구된다.

정책 변경이 반복되는 환경에서 살아남는 서비스는 '한 번 잘 붙은 API'가 아니라, 변화에 대응할 수 있는 실행 레이어를 가진 서비스라는 것이 셀라 네트워크의 주장이다. X의 보상형 게시 앱 퇴출과 맞물린 인포파이 중지 흐름이 확산하는 가운데, 셀라 네트워크가 내세운 '탈중앙 노드 기반 웹 액세스'가 실제로 팀들의 재구축 표준으로 자리 잡을지 주목된다.
