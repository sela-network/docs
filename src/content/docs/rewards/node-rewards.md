## 보상 구성 요소

노드 운영자는 다음 방식으로 보상을 받습니다:

### 1. 기본 네트워크 보상

**개념:**

- 네트워크 유지에 기여한 대가로 지급
- 블록 생성 또는 검증 참여 시 보상

**보상 방식:**

```
기본 보상 = 네트워크 인플레이션 풀에서 배분
노드별 배분 = (노드 스테이킹 / 전체 스테이킹) × 블록 보상
```

### 2. 트랜잭션 수수료

**개념:**

- API 요청 처리에 대한 직접적인 보상
- 사용자가 지불한 수수료의 일부

**배분 구조:**

```
API 호출 수수료: 가변 (수요에 따라)
  ├─ 70% → 요청 처리 노드
  ├─ 20% → 프로토콜 재무
  └─ 10% → 소각
```

### 3. 성능 인센티브

**평가 지표:**

- **응답 시간**: 빠른 응답 제공 시 보너스
- **가동시간**: 높은 uptime 유지 시 보너스
- **성공률**: 요청 성공률에 따른 보너스

**등급 체계:**
| 등급 | 성능 점수 | 보너스 |
|------|-----------|--------|
| S | 95+ | +30% |
| A | 90-94 | +20% |
| B | 85-89 | +10% |
| C | 80-84 | +5% |
| D | < 80 | 0% |

## 노드 티어

### Micro Node

```
최소 스테이킹: 100 SELA
예상 처리량: 하루 50-100 요청
예상 월 수익: 변동 (시장 수요 따라)
```

### Standard Node

```
최소 스테이킹: 1,000 SELA
예상 처리량: 하루 500-1,000 요청
예상 월 수익: 변동 (시장 수요 따라)
```

### Professional Node

```
최소 스테이킹: 5,000 SELA
예상 처리량: 하루 2,000-5,000 요청
예상 월 수익: 변동 (시장 수요 따라)
```

**주의사항:**

- 모든 수익은 네트워크 사용량과 $SELA 토큰 가격에 따라 변동
- 과거 수익이 미래 수익을 보장하지 않음

## 스테이킹 요구사항

### 목적

- 네트워크 보안 강화
- 악의적 행위 방지
- 노드 품질 보장

### 스테이킹 규모별 혜택

| 스테이킹         | 우선순위 | 기타 혜택     |
| ---------------- | -------- | ------------- |
| 100-999 SELA     | 일반     | -             |
| 1,000-4,999 SELA | 중간     | 통계 대시보드 |
| 5,000-9,999 SELA | 높음     | 전용 지원     |
| 10,000+ SELA     | 최우선   | 거버넌스 참여 |

## 슬래싱 (Slashing)

### 패널티 대상

**심각한 위반:**

- 데이터 조작 시도
- 거짓 증명 생성
- 네트워크 공격 참여

**경미한 위반:**

- 지속적인 다운타임
- 낮은 서비스 품질
- SLA 위반

### 패널티 수준

| 위반 유형   | 1차       | 2차       | 3차       |
| ----------- | --------- | --------- | --------- |
| 데이터 조작 | 전액 몰수 | -         | -         |
| 낮은 품질   | 경고      | 일부 감소 | 자격 박탈 |
| 다운타임    | 경고      | 경고      | 일부 감소 |

## 보상 청구

- 기본 보상: 주기적 자동 지급
- 수수료: 실시간 누적
- 보너스: 월 1회 정산


## FAQ

**Q: 스테이킹한 토큰은 언제 돌려받나요?**
A: 노드 운영 중단 시 언제든 회수 가능합니다. 단, 패널티가 있는 경우 감액될 수 있습니다.

**Q: 수익은 어떻게 계산되나요?**
A: (처리한 요청 수 × 수수료율) + 기본 보상 + 성능 보너스로 계산됩니다.

**Q: 노드가 오프라인이면 패널티가 있나요?**
A: 일시적 오프라인은 괜찮습니다. 지속적으로 오프라인(uptime < 95%)인 경우 보상이 감소할 수 있습니다.
