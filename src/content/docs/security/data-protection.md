## 데이터 보호 원칙

### Privacy by Design

**핵심 원칙:**

1. **사전 예방** (Proactive not Reactive)
2. **기본 설정으로 프라이버시** (Privacy as Default)
3. **설계에 내장** (Embedded into Design)
4. **완전한 기능** (Full Functionality)
5. **종단간 보안** (End-to-End Security)
6. **가시성과 투명성** (Visibility and Transparency)
7. **사용자 중심** (Respect for User Privacy)

## 데이터 분류

### Tier 1: 공개 데이터

```
예시:
- API 문서
- 블록체인 트랜잭션 (공개)
- 네트워크 통계

보호 수준: 무결성 보호
```

### Tier 2: 내부 데이터

```
예시:
- 시스템 로그
- 성능 메트릭
- 에러 로그

보호 수준: 접근 제어 + 암호화
```

### Tier 3: 민감 데이터

```
예시:
- API Keys
- 사용자 이메일
- 결제 정보

보호 수준: 강력한 암호화 + 엄격한 접근 제어
```

### Tier 4: 매우 민감한 데이터

```
예시:
- 패스워드 해시
- 개인 키
- 재무 정보

보호 수준: 최고 수준 암호화 + 감사 로그
```

## 암호화

### 저장 데이터 (Data at Rest)

**암호화 방식:**

```
알고리즘: AES-256-GCM
키 관리: 외부 KMS (Key Management Service)
키 회전: 자동 (90일)
```

**적용 범위:**

```
✅ 데이터베이스 (PostgreSQL TDE)
✅ 파일 스토리지 (S3 SSE)
✅ 백업 (암호화된 백업)
✅ 로그 (민감 정보 포함 시)
```

---

### 전송 데이터 (Data in Transit)

**프로토콜:**

```
TLS 버전: 1.3 (최소 1.2)
Cipher Suites (우선순위):
  1. TLS_AES_256_GCM_SHA384
  2. TLS_CHACHA20_POLY1305_SHA256
  3. TLS_AES_128_GCM_SHA256

Certificate Authority: Let's Encrypt
키 길이: RSA 4096-bit 또는 ECDSA P-384
```

**적용 범위:**

```
✅ API 통신 (HTTPS)
✅ 웹소켓 (WSS)
✅ 데이터베이스 연결 (SSL)
✅ 노드 간 통신
```

---

### 사용 중 데이터 (Data in Use)

**메모리 보호:**

```
- Secure Enclave (가능한 경우)
- Memory Encryption
- 사용 후 즉시 삭제 (Zero-out)
```

## 개인정보 처리

### 최소 수집 원칙

**수집하는 정보:**

```
✅ 필수:
   - 이메일 (계정 관리)
   - API 사용 통계 (과금)

❌ 수집하지 않는 정보:
   - 웹 페이지 내용 (저장 안 함)
   - 브라우징 히스토리
   - 위치 정보
```

---

### 익명화 및 가명화

**로그 처리:**

```javascript
// IP 주소 익명화
const anonymizeIP = (ip) => {
  // IPv4: 192.168.1.100 → 192.168.1.0
  // IPv6: 2001:db8::1 → 2001:db8::
  return ip.split(".").slice(0, -1).join(".") + ".0";
};

// 이메일 마스킹
const maskEmail = (email) => {
  // user@example.com → u***@e***.com
  const [name, domain] = email.split("@");
  return `${name[0]}***@${domain[0]}***.${domain.split(".").pop()}`;
};
```

## 접근 제어

### RBAC (Role-Based Access Control)

**역할 정의:**

```
Admin (관리자):
  - 모든 데이터 접근 가능
  - 시스템 설정 변경 가능
  - 제한: 2FA 필수, IP 제한

Developer (개발자):
  - 코드 저장소 접근
  - 테스트 환경 접근
  - 제한: 프로덕션 데이터 접근 불가

Support (지원팀):
  - 사용자 데이터 조회 (읽기 전용)
  - 티켓 시스템
  - 제한: 민감 정보 마스킹

Auditor (감사자):
  - 로그 조회 (읽기 전용)
  - 보안 리포트
  - 제한: 데이터 수정 불가
```

## 데이터 삭제 권리

### GDPR Right to be Forgotten

**사용자 요청 시:**

```
1. 신원 확인 (이메일 + 2FA)
2. 삭제 범위 확인
3. 30일 이내 완전 삭제
4. 삭제 확인서 발급
```

**삭제 프로세스:**

```
Step 1: 계정 비활성화
Step 2: 개인정보 삭제
Step 3: 백업에서 삭제 (다음 백업 사이클)
Step 4: 삭제 완료 통지
```

**예외:**

- 법적 의무로 보관 필요한 정보 (과금 기록 등)
- 익명화하여 통계 목적으로 보관

## 데이터 유출 대응

### 탐지

**모니터링:**

```
- 비정상적인 데이터 접근
- 대량 데이터 다운로드
- 권한 없는 접근 시도
- 외부로의 비정상 전송
```

**자동 알림:**

- 보안팀 즉시 알림
- 관련 시스템 자동 격리

---

### 대응 절차

**24시간 내:**

```
1. 피해 범위 파악
2. 추가 유출 차단
3. 내부 보고
```

**72시간 내:**

```
1. 규제 기관 신고 (GDPR 요구사항)
2. 영향받은 사용자 통지
3. 대응 조치 실행
```

**1주일 내:**

```
1. 근본 원인 분석
2. 재발 방지 대책
3. 공개 보고서 발표 (심각한 경우)
```

## FAQ

**Q: 내 데이터는 어디에 저장되나요?**
A: 계정 생성 시 선택한 지역의 데이터센터에 저장됩니다. 기본적으로 가장 가까운 지역입니다.

**Q: 데이터를 완전히 삭제하려면?**
A: 계정 설정 → 데이터 삭제 → 확인. 30일 이내 완전히 삭제됩니다.

**Q: 데이터 유출 시 알림을 받나요?**
A: 네, 72시간 이내에 이메일로 통지받습니다.
