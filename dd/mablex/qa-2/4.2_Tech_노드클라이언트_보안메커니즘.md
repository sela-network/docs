# 노드-클라이언트 간 보안 리스크 방지 메커니즘

## 질문
노드-클라이언트 간 보안 리스크 방지 매커니즘: 노드가 제3자의 세션에 접근하거나, 반대로 클라이언트가 악의적으로 노드 운영자의 개인정보를 탈취할 수 있는 가능성을 방지하기 위한 보안 메커니즘 여부

## 답변

노드 운영자의 개인 브라우저 및 로컬 파일 시스템은 완전히 보호됩니다. 클라이언트는 Agent Node 전용 프로필에만 접근 가능하며, Whitelist에 등록된 웹 도메인 그리고 플랫폼별 Permission과 클라이언트의 의도 Permission으로 접근 제어됩니다.

1. 브라우저 격리
- Agent Node 전용 프로필 사용
- 노드 운영자의 개인브라우져와 완전 분리
- 노드 운영자는 Agent Node 전용 브라우저에서 별도로 로그인하며, 이 세션만 클라이언트에게 제공

2. 로컬 파일 접근 차단
- http(s)외의 URL 검증 단계에서 차단
- 노드 운영자의 로컬 파일 시스템 접근 불가

3. 클라이언트 인증 및 세션 격리
- JWT/JWKS 기반 API 키 인증 시스템
- 세션별 고유 ID 발급 및 탭 단위 격리

4. 접근 제어
- URL Whitelist로 허용된 도메인만 접근 가능
- Blacklist로 민감 도메인 명시적 차단
- 플랫폼별 Permission, 의도 Permission 시스템으로 노드 운영자가 직접 제어
- Rate Limiting (10 req/min) 및 Daily Limits
