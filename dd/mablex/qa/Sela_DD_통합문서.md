D2A 및 GrowlOps 수익 모델 (각 수익원에 대한 상세 설명)

1. Browse API (D2A / Web Access API)

  AI agent 사업자, 버티컬 AI agent 빌더, 기타 데이터접근이 필요한 기업 대상 web access API 제공

  (1) Researcher (Free)
    - 월 1,000 API credits 무료 제공
    - 신용카드 등록 불필요
    - 이메일 서포트
    - 목적: 개발자/리서처 온보딩, 제품 체험

  (2) Pay As You Go
    - $0.0064 / credit
    - 사용한 만큼만 결제
    - 이메일 서포트, 언제든 취소 가능
    - Production-grade API keys
    - 종량제 청구 (Billed incrementally)
    - 목적: 유동적 사용량, 초기 스타트업

  (3) Monthly Plans (구독형)
    - Project: 4,000 cr/mo, $24/mo ($0.006/cr)
    - Bootstrap: 15,000 cr/mo, $80/mo ($0.0053/cr)
    - Startup: 38,000 cr/mo, $176/mo ($0.0046/cr)
    - Growth: 100,000 cr/mo, $400/mo ($0.004/cr)
    - Pay as you go 모드: 초과 사용 시 기본 요금($0.0064/cr)으로 자동 과금
    - Auto upgrade 모드: 사용량 초과 시 자동으로 상위 플랜으로 업그레이드
    - 목적: 예측 가능한 비용 관리, 볼륨 디스카운트 혜택

  (4) Enterprise (Custom)
    - 볼륨 디스카운트
    - Custom rate limits
    - Enterprise-Grade support & SLAs
    - Custom Single Sign-On (SSO)
    - MSA & DPA 지원
    - 전용 Slack 채널, 아키텍처 가이던스 제공
    - 목적: 대기업, 고볼륨 사용자


2. API Credits Breakdown

  (1) Browse Search

    - Advanced search: 2 credits / query

    - Basic extract: 1 credit / 5 URLs

  (3) Browse Map

    - With instructions: 1 credit / 5 URLs

  (4) Browse Crawl
    - Map pricing + Extract pricing


3. 플랫폼별 프리미엄

4. GrowlOps (소셜 캠페인 X 마인드쉐어 Analytics)

  프로젝트/마케팅 팀이 커뮤니티/캠페인을 "실행→측정→최적화"하도록 하는 운영툴(Ops) 제공

  (1) 초기 단계
    - 무료 제공 + 파트너십 및 코마케팅

  (2) 구독 형태
    - 월단위 추적 키워드, 포스트 수 종량제, 검색 키워드 수에 따른 과금

    - 캠페인 수, 데이터 보존기간에 따른 별도 티어 운영

  (3) Usage 기반
    - 이벤트/캠페인 추적량, 대시보드 갱신 빈도, 분석 리포트 생성량 등에 따라 과금

1.2 타 노드 프로젝트 대비 차별화 포인트

[질문]
타 노드(또는 디핀) 프로젝트 대비 사업적/기술적 차별화 포인트

[답변]

Data DePIN 대표 프로젝트 Grass와 비교


1. 기술 아키텍처 차별성

  (1) Grass: Bandwidth/Proxy 기반
    - 단순 IP/대역폭 공유 모델
    - 퍼블릭 데이터/메타데이터 수집 중심
    - 노드가 "파이프" 역할만 수행

  (2) Sela: Browser Execution 기반
    - 인증 계정 + Residential IP 기반 실제 브라우저 실행
    - 클릭, 스크롤, 입력 등 복합 웹 액션 수행 가능
    - 노드가 "실행 엔진" 역할 수행
    - Human-like behavior 시뮬레이션으로 탐지 우회


2. 서비스 역량 차별성

  Grass로 불가능 / Sela로 가능한 것:
    - LinkedIn에서 특정 조건 만족하는 B2B 리드 검색 및 프로필 수집
    - X에서 조건별 프로필 검색 및 팔로워 분석
    - Instagram에서 트렌딩 키워드/해시태그 데이터 수집
    - 로그인 필요 페이지 접근 및 데이터 추출
    - 동적 렌더링 페이지(SPA) 크롤링
    - 폼 입력, 버튼 클릭 등 인터랙티브 액션 실행


3. 비즈니스 모델 차별성

  (1) Grass
    - AI 학습용 데이터셋 판매 (B2B2C)
    - 노드 운영자에게 토큰 리워드만 제공
    - 데이터 품질/성공률 보장 없음

  (2) Sela
    - Web Access API 직접 판매 (B2B SaaS)
    - 성공 기반 과금 (성공한 요청만 과금)
    - SLA 보장: 성공률 99%+, 응답시간 보장, 동시성 제어


4. 노드 운영자 관점 차별성

  (1) Grass
    - 어떤 데이터가 수집되는지 알 수 없음 (블랙박스)
    - 노드 운영자 통제권 없음
    - 잠재적 법적 리스크 노출

  (2) Sela
    - 모든 web execution 내역 투명하게 기록/공개
    - 노드 운영자가 허용 도메인/작업 유형 선택적 제한 가능
    - 민감 사이트(금융, 정부 등) 자동 필터링
    - 노드별 명확한 리워드 산정 기준 (uptime + execution quality)


5. 확장성 차별성

  (1) Grass: 단일 use case (데이터 수집)

  (2) Sela: 다중 use case 확장 가능
    - Browse API: AI Agent용 웹 액세스
    - GrowlOps: 소셜 마케팅 분석 도구
    - Future: RPA 자동화, 가격 모니터링, 광고 검증 등

1.3 경쟁사 대비 Sela 선택 이유

[질문]
고객들이 기존 솔루션(Browserbase, Apify, Bright Data 등) 대신 Sela를 선택해야할 이유

[답변]


1. Sela vs 경쟁사 비교

  (1) vs. Bright Data
    - 비용: 중앙화 인프라(데이터센터/서버) → Sela는 분산 노드 유휴 자원 활용으로 가격 경쟁력
    - 기능: 데이터 수집 특화 → Sela는 데이터 수집 + AI Agent action 실행 가능

  (2) vs. Apify
    - 포지션: 자동화 소프트웨어 마켓플레이스(플랫폼) → Sela는 AI Agent 실행 인프라(인프라 레이어)
    - 사용성: 개발자가 스크립트 작성/관리 필요 → Sela는 API 호출만으로 웹 액션 실행

  (3) vs. Browserbase (가장 직접적 경쟁)
    - 스케일링: 중앙화 서버 기반, 증설 필요 → Sela는 분산 노드로 자연스럽게 스케일링
    - 성공률: 서버 IP 기반, 대량 요청 시 차단 리스크 → Sela는 Residential IP + 인증계정으로 Human-like action


2. Sela 핵심 차별점 요약

  - 비용 구조: 중앙화 인프라 비용 없이 분산 노드 유휴 자원 활용
  - 스케일링: 노드 네트워크 확장으로 무제한 동시 세션 지원
  - 성공률: Residential IP + 인증계정 + Human-like action → 99%+ SLA
  - 유연성: 데이터 수집 + AI Agent action + 향후 RPA 확장
  - 투명성: 노드 운영자/고객 모두에게 실행 내역 공개


3. 경쟁사 현황

  (1) Bright Data (Israel, 2002년 설립)
    - 매출: $300M ARR (2025), $400M 목표 (2026)
    - 고객: 20,000+ 기업
    - 팀: 300+ 명
    - 특징: Web data infrastructure 시장 1위, 중앙화 프록시/스크래핑 서비스
    - 투자: EMK Capital에 ~$200M에 인수 (2017)

  (2) Apify (Czech, 2015년 설립)
    - 매출: $13.3M (2024), YoY 80% 성장
    - 고객: Siemens, Microsoft, T-Mobile, Accenture
    - 팀: 86-116명
    - 특징: 클라우드 기반 웹 스크래핑 플랫폼 + 자동화 마켓플레이스
    - 투자: $2.98M (대부분 자체 수익으로 성장)

  (3) Browserbase (US, 2024년 설립)
    - 매출: $3-4M (2025)
    - 고객: Perplexity, Vercel, 11x 등 1,000+ 기업
    - 팀: 30-40명
    - 특징: AI Agent용 헤드리스 브라우저 인프라, 가장 직접적 경쟁사
    - 투자: $67.5M 누적 (Seed $6.5M → Series A $21M → Series B $40M)
    - 밸류에이션: $300M (2025.04 Series B 기준)

2.2 웹3 커뮤니티 활성화 및 마케팅 전략

[질문]
웹3 커뮤니티 활성화 및 노드 운영자 유입 관련 구체적인 마케팅 전략 (에어드랍, KOL 마케팅, 예산 등)

핵심 컨셉: GrowlOps + 노드 네트워크를 활용한 저비용 고효율 커뮤니티 성장 전략

  (1) 핵심 KPI: 업타임 90% 이상 유지 노드 수
    - 단순 노드 수가 아닌 "품질 노드" 기준으로 측정
    - 2026 목표: 100,000 품질 노드 (업타임 90%+)
    - 2027 TGE 시점: 300,000 품질 노드

  (2) 성장 방식: Product-led Growth (PLG)
    - KOL 의존형 대량 마케팅 배제
    - 제품 품질 + 보상 기대감 + 자체 인프라 활용이 핵심 레버

  (3) X(Twitter) 알고리즘 최적화 콘텐츠 검증
    - 자체 캠페인(Selping)을 통해 X(Twitter) 알고리즘에 최적화된 콘텐츠 패턴 검증 완료
    - 포스트당 평균 조회수 875회, 총 조회수 437,457회 달성 (1개월 기준)
    - 검증된 콘텐츠 패턴을 GrowlOps 기반 마케팅에 적용하여 고효율 달성


2. GrowlOps 활용 - 웹3 프로젝트 커뮤니티 흡수

  전략: GrowlOps 도입 프로젝트와 단계별 코마케팅 → 자연스러운 커뮤니티 유입 → 노드 전환

  (1) 1차 - 인지
    - 프로젝트 런칭 전후 공동 캠페인 진행
    - Sela x 파트너 프로젝트 공동 콘텐츠 제작
    - 상호 커뮤니티 노출로 Sela 인지도 확보

2.5 TGE 이후 노드 운영자 이탈 방지 전략

[질문]
TGE 이후 노드 운영자 이탈 방지(락인) 전략

[답변]

핵심 원칙: 하방경직적 경제 구조 + 업타임 기반 보상 + NFT 장착 시스템 + 거버넌스 참여를 통한 다층적 락인


1. 하방경직 경제 구조

  (1) 기본 메커니즘
    - 노드 이탈 → 남은 노드에 배분되는 보상 풀 비중 증가
    - 이탈자 발생 시 잔류자의 기대 수익 상승 → 추가 이탈 억제
    - 네트워크 규모 축소에도 운영자 수익은 유지/상승하는 자연스러운 하방 지지

  (2) 실사용 연동
    - API 호출량/성공률에 따른 추가 인센티브
    - 매출 성장과 노드 보상 직접 연동 → "네트워크 성장 = 내 수익 성장"


2. 업타임 기반 보상 체계

  (1) 티어별 보상 멀티플라이어
    - Tier 1 (80-89%): 기본 보상 (1.0x)
    - Tier 2 (90-94%): 1.2x 보상
    - Tier 3 (95-98%): 1.5x 보상
    - Tier 4 (99%+): 2.0x 보상

  (2) 운영 방식
    - 7일 롤링 평균으로 업타임 산정
    - 매주 티어 재산정 → 지속적 고품질 운영 유도
    - 80% 미만 시 작업 배정 중단 (3.3 슬래싱 조건과 연동)

  (3) 효과
    - 단순 노드 수 확보가 아닌 품질 노드 유지에 집중
    - 성실한 운영자에게 차등 보상 → 장기 운영 동기 강화
    - 네트워크 전체 안정성/성공률 향상


3. API 특화 NFT 시스템

  (1) 컨셉
    - 플랫폼별 NFT를 구매/장착하여 해당 API 작업 수행 시 보상률 증가

  (2) 지원 플랫폼별 NFT
    - X Access NFT
    - LinkedIn Access NFT
    - Medium Access NFT
    - (향후 Instagram, TikTok 등 확장)

  (3) NFT 등급 및 보상 부스트
    - Common: +10% 보상
    - Rare: +20% 보상
    - Epic: +35% 보상
    - Legendary: +50% 보상

  (4) 스태킹 효과
    - 복수 플랫폼 NFT 장착 시 추가 보너스
    - 3개 이상 장착: 전체 보상 +10% 추가
    - 5개 이상 장착: 전체 보상 +20% 추가

  (5) NFT 획득 방식
    - SPWR 포인트로 구매 (포인트 소각)
    - 한정판 NFT 드롭 이벤트
    - 장기 운영자 대상 무료 지급 (마일스톤)

  (6) 효과
    - NFT 구매 = 포인트 소각 → 토큰 희소성 증가
    - 이미 투자한 NFT → 이탈 시 손실 → 전환 비용 생성
    - 플랫폼별 전문화 경로 → 차별화된 운영 전략
    - 2차 시장 형성 가능 → 추가 생태계 확장


4. SPWR 거버넌스 참여

  (1) 투표 가능 정책
    - 신규 지원 플랫폼 우선순위 결정
    - 보상률 조정 제안
    - NFT 드롭 이벤트 기획
    - 네트워크 파라미터 변경 (슬래싱 비율 등)

  (2) 투표력 산정
    - 기본: 포인트 보유량에 비례
    - 가중치: 노드 운영 기간에 따른 보너스 (OG 운영자 우대)
    - 락업 보너스: 스테이킹 기간이 길수록 투표력 증가

  (3) 효과
    - 단순 보상 수령자 → 네트워크 의사결정 주체로 전환
    - 정책 참여 → 소속감/오너십 강화
    - 장기 보유 유도 (투표력 극대화 위해)

3.3 업타임 유지 및 슬래싱 조건

[질문]
노드 운영자의 업타임 유지 조건과 슬래싱(패널티) 메커니즘은 어떻게 설계되어 있나요?

[답변]

1. 업타임 유지 조건

네트워크 참여 노드는 유연한 참여 환경을 제공하면서도 서비스 품질을 유지하기 위해 등급제 시스템을 운영합니다.

  (1) 기본 조건
    - 생존 신호(Heartbeat): 5분 간격으로 네트워크에 생존 신호 전송
    - 측정 기준: 24시간 이동 평균 응답률 적용
    - 신규 노드 유예 기간: 최초 참여 후 7일간 페널티 없이 안정화 기간 제공

  (2) 등급별 보상 체계
    - Gold (응답률 95% 이상): 기본 보상 + 20% 보너스, 우선 작업 배정
    - Silver (응답률 80% 이상): 기본 보상 100% 지급
    - Bronze (응답률 60% 이상): 기본 보상의 70% 지급
    - 60% 미만: 보상 지급 중단, 단 작업 배정은 유지 (복구 기회 제공)

  (3) 복구 방안
    - 응답률이 60% 미만으로 하락한 노드는 24시간 내 60% 이상 회복 시 즉시 보상 재개
    - 별도의 대기 기간 없이 실시간 응답률 기반으로 등급 자동 조정


2. 슬래싱 조건

노드 운영자는 네트워크 참여 시 SPWR 포인트를 보증금으로 예치(스테이킹)해야 합니다.

  (1) 신규 노드 예치 방안
    - 최소 예치금: 1,500 SPWR 포인트
    - 예치 유예 기간: 최초 7일간 예치 없이 노드 운영 가능
    - 자동 적립: 유예 기간 동안 보상의 50%가 예치금으로 자동 적립 (7일 운영 시 최소 예치금 충족)
    - 정상 전환: 7일 후 최소 예치금 충족 시 정상 운영으로 전환, 이후 보상 100% 수령
    - 미충족 시: 최소 예치금 미충족 시 자동 적립 지속 (충족까지)

  (2) 경고 시스템 (슬래싱 전 단계)
    - 1차 경고: 48시간 연속 오프라인 시 알림 발송
    - 2차 경고: 72시간 연속 오프라인 시 작업 배정 일시 중단
    - 슬래싱은 경고 후에도 개선되지 않을 경우에만 적용

  (3) 슬래싱 적용 기준
    - 연속 오프라인 (7일 초과): 예치금의 5% 차감 - 장기 방치로 간주
    - 잘못된 결과 제공 (3회 이상 반복): 10% 차감 - 의도적 오류로 간주
    - 악의적 행위 (검증된 경우): 20~30% 차감 - 네트워크 공격 시도 등
    - 슬래싱된 SPWR 포인트는 전량 소각 처리 (디플레이션 효과)

  (4) 슬래싱 면제 조건
    - 사전 오프라인 신고: 최대 14일까지 휴면 모드 신청 가능 (슬래싱 면제)
    - 네트워크 장애: 전체 네트워크 이슈로 인한 오프라인은 면제


3. 메커니즘의 의의

  - 제로 진입 장벽: 신규 운영자도 SPWR 포인트 없이 즉시 참여 가능
  - 자연스러운 예치금 형성: 운영하면서 자동으로 예치금 적립
  - 포인트 순환 구조: SPWR 획득 → 예치 → 거버넌스 참여로 이어지는 일관된 생태계
  - 관용적 패널티: 경고 시스템과 면제 조건을 통해 실수에 대한 복구 기회 제공

    - 고객은 Fiat/스테이블코인으로 서비스 결제
    - 매출의 일정 비율로 시장에서 $SELA 바이백 후 소각
    - 실매출 증가 → 바이백 증가 → 토큰 공급 감소 → 가치 상승

    - 실질적인 Fiat 매출 확보 (명확한 비즈니스 검증)
    - 토큰 매도 압력 없음 (운영비를 위한 토큰 판매 불필요)

9.1 대규모 Detection 정책 변경 대응

[질문]
특정 웹사이트(X, LinkedIn 등)에서 대규모 detection 관련 정책 변경 시 대응 프로세스

[답변]

Sela는 실시간 모니터링, 자동화된 즉시 대응, 단계별 기술 대응, 리스크 분산 전략을 통해 플랫폼 정책 변경에 체계적으로 대응합니다.


1. 실시간 모니터링 체계

  (1) 성공률 대시보드
    - X, LinkedIn, Instagram 등 주요 플랫폼별 성공률/실패율 실시간 모니터링
    - 성공률 급락 시 즉시 알람 (예: 95% → 70% 이하)

  (2) 원인 자동 분류
    - CAPTCHA 증가, 세션 만료, DOM 구조 변경, Rate-limit, IP 차단 등 유형별 자동 분류
    - 원인별 맞춤 대응 프로세스 자동 실행


2. 즉시 대응 (1~24시간)

  (1) 자동 라우팅 전환
    - 탐지된 리전/노드군에서 다른 리전 노드로 자동 라우팅
    - Rate-limit 감지 시 요청 간격 자동 조정

  (2) 세션 관리
    - 세션 기반 차단 시 세션 로테이션 주기 단축
    - 쿠키/토큰 갱신 자동화

  (3) 고객 커뮤니케이션
    - 영향받는 API 사용자에게 상황 및 예상 복구 시간 즉시 안내


3. 단기 대응 (1~7일)

  (1) 핑거프린트 업데이트
    - 탐지 패턴 분석 후 브라우저 핑거프린트 다양화
    - User-Agent, 헤더 로테이션 패턴 변경

  (2) 행동 패턴 조정
    - Human-like action 패턴 업데이트 (클릭 간격, 스크롤 속도 등)
    - 자연스러운 사용자 행동 시뮬레이션 강화

  (3) 대체 경로 확보
    - 동일 데이터 접근 가능한 대체 엔드포인트/방식 탐색


4. 중장기 대응 (1주~1개월)

  (1) 플랫폼별 전담 대응
    - 주요 플랫폼별 정책 변경 지속 트래킹
    - 새로운 탐지 기법 분석 및 대응 기술 R&D

  (2) 노드 품질 관리
    - 탐지율 높은 노드 자동 비활성화
    - 품질 기준 미달 노드 슬래싱

  (3) SLA 정책 관리
    - 특정 플랫폼 성공률 장기 저하 시 고객에게 SLA 조건 사전 고지


5. 고객 커뮤니케이션 체계

  (1) 실시간 상태 공개
    - 플랫폼별 API 상태 페이지 운영
    - 정책 변경 감지 시 고객에게 선제적 안내

  (2) 대안 제시
    - 특정 플랫폼 장기 이슈 시 대체 접근 방식 가이드 제공


6. 리스크 분산 전략

  (1) 플랫폼 의존도 관리
    - 특정 플랫폼 매출 비중 50% 이하 유지 목표

  (2) 노드 지역 다변화
    - 단일 국가 노드 비중 30% 이하 유지

  (3) 기술 스택 다양화
    - 단일 우회 기법 의존 방지
    - 다중 접근 방식 병행으로 기술 리스크 분산


7. 대응 체계 요약

  - 실시간 모니터링으로 이상 징후 즉시 감지
  - 자동화된 라우팅/세션 관리로 1차 대응
  - 핑거프린트/행동 패턴 업데이트로 단기 대응
  - 플랫폼별 전담 대응 및 R&D로 중장기 대응
  - 플랫폼/노드/기술 다변화로 리스크 분산

9.2 국가별 규제 및 법적 제한 대응 방안

[질문]
IP, Bandwidth, 데이터 수집 관련 국가별 규제 및 법적 제한 대응 방안

[답변]

Sela는 데이터 보관을 하지 않는 실행 인프라로, 노드 운영자가 허용할 플랫폼과 액션 범위를 직접 선택할 수 있어 국가별 규제 리스크를 최소화합니다.


1. 노드 운영자 동의 기반 운영

  (1) 선택적 허용
    - 노드 운영자는 본인의 IP와 (선택적으로) 보유 계정을 기반으로 허용할 웹사이트/도메인 및 접근 유형(예: post-login 포함)을 직접 선택
    - 동의하지 않은 대상은 실행되지 않도록 정책으로 제한

  (2) 투명한 운영
    - 노드 활동은 투명하게 공개되어 운영자가 인지 가능
    - 운영자는 언제든지 허용 플랫폼과 액션 변경 가능


2. 책임 분리 구조

  (1) 고객 (수요자)
    - 접근 권한 및 사용 목적의 적법성 책임
    - 데이터 접근 및 웹 액션에 대한 법적 책임

  (2) 노드 운영자 (공급자)
    - 자신이 동의한 범위에서만 서비스 제공
    - 원치 않는 사이트/행동은 거부 가능

  (3) Sela Network (플랫폼)
    - 클라이언트 요청과 노드 운영자 허용/실행 내역을 블록체인에 기록
    - 추후 감사 및 분쟁 대응 가능한 네트워크 제공


3. 국가별 리스크 대응

  (1) 노드 참여 및 라우팅 정책
    - 규제 리스크가 높은 국가에서는 노드 참여/트래픽 유형 제한
    - 필요시 특정 국가로의 라우팅 차단

  (2) 금지 사용 정책
    - 화이트/블랙리스트 사이트 관리
    - 불법 접근, 무단 계정 사용, 악성 자동화 등 명시적 금지
    - 위반 시 차단 및 제재

  (3) 감사/추적 가능성
    - "누가/언제/어디로(도메인)/어떤 유형의 요청" 수준의 메타데이터 기록
    - 분쟁 및 규제 문의 대응 가능


4. 대응 방안 요약

  - 데이터 미보관 구조로 개인정보 규제 리스크 최소화
  - 노드 운영자 동의 기반으로 책임 분리 명확화
  - 블록체인 기록으로 투명성 및 감사 가능성 확보
  - 국가별 맞춤 정책으로 유연한 규제 대응
