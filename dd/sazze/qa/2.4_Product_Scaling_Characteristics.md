# Scaling Characteristics

## 질문
Which parts of your system scale linearly with usage, and which scale non-linearly?

## 답변

선형 스케일링 (Linear):
- API 요청 처리: 요청 수에 비례하여 노드 리소스 소비
- 매출: 사용량 기반 과금으로 요청 수에 비례

비선형 스케일링 (Sub-linear, 유리):
- 인프라 비용: DePIN 구조로 노드 증가 시 한계비용 감소 (중앙화 서버 증설 불필요)
- 노드 보상: 처리량에 비례하여 노드 운영자에게 보상되며 지급량은 일정 수준으로 제한됨.
- 시맨틱 엔진: 한 번 구축 후 모든 고객이 공유, 추가 비용 없이 활용
- 플랫폼 커버리지: 노드 증가 시 지역/플랫폼 커버리지가 비례 이상으로 확장

네트워크 효과 (Super-linear):
- 노드 증가 → 성공률/커버리지 향상 → 클라이언트 증가 → 노드 수익 증가 → 더 많은 노드 유입
- 임계점 이후 자기강화적 성장 구조

핵심: 비용은 sub-linear, 가치는 super-linear로 스케일링되는 구조

---

## Answer (English)

Linear Scaling:
- API request processing: Node resource consumption proportional to number of requests
- Revenue: Proportional to number of requests through usage-based billing

Non-linear Scaling (Sub-linear, Advantageous):
- Infrastructure costs: Marginal costs decrease as nodes increase with DePIN structure (no centralized server expansion needed)
- Node rewards: Rewards paid to node operators proportional to throughput, but payout amounts are capped at a certain level
- Semantic engine: Built once and shared by all customers, utilized at no additional cost
- Platform coverage: Region/platform coverage expands more than proportionally as nodes increase

Network Effects (Super-linear):
- More nodes → Higher success rate/coverage → More clients → Higher node revenue → More node influx
- Self-reinforcing growth structure after reaching critical mass

Core: Structure where costs scale sub-linearly while value scales super-linearly
